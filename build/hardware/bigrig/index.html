MEMORY BUDGET

Fit the whole system, not only the weights.

The 20 GB Q5_K_M weight set plus 128K q8_0 KV cache fit in 28 GB combined VRAM (about 15.4 GiB + 11.6 GiB in use); the 32 GB DDR4-3600 host RAM is the offload tier and stays out of the hot path.

BOTTLENECK

Bandwidth sets the ceiling.

27B dense decode is memory-bandwidth bound across two VRAM pools; documented decode falls from 19.5 tok/s at 28K context to 14.1 at 80K and 12.4 at 120K as the KV cache grows, which is why the 256K deep mode drops speculative decoding.

PUBLIC-SAFE NOTES

  • Dual-GPU desktop on a MSI PRO Z690-A WIFI board (MS-7D25); the iGPU runs the display, leaving both dGPUs for compute
  • One llama.cpp server drives both dGPUs through Vulkan (RADV on the 9060 XT, NVIDIA Vulkan on the 3060); whole layers split 16-11 (-sm layer -ts 16,11) to match the 16 GB / 12 GB VRAM ratio
  • Daily config changed from llama.cpp defaults for this model: 128K context (default 4K), flash attention on, q8_0 KV cache (default f16), MTP speculative decoding n=2 (default off)
  • MTP adds +71 to +98 percent decode (14.1 to 24.1 tok/s on 400-token agent rounds) at a cost of roughly 40 percent raw prefill on uncached prompts; agent prefix caching absorbs that
  • Draft-model KV must be quantized (-ctkd/-ctvd q8_0); at 128K context the f16 draft KV overflows the 12 GB card and crash-looped until it was set
  • llama-switch toggles three modes: mtp (daily 128K), deep (256K, q5_1 KV, no spec), split (one card per agent lane on separate ports)
  • 952 GB NVMe root with large headroom for working sets
