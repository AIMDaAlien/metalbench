// 01 · who runs the machines

The human behind the machine

Aim is the person you call when a 24B model refuses to fit in VRAM, when an agent loop burns through context like it's free, and when the 9060 XT hits 84°C at 2 a.m. LLMops is the job: the unglamorous, deeply satisfying work of making large models run reliably on the machines in the room next to you.

This one machine is the whole fleet: an i5-13600K on a Z790 board, 30 GiB of DDR5, and three GPUs doing three jobs. The Radeon RX 9060 XT serves the big model, the RTX 3060 serves the small one, and the UHD 770 runs the display. All inference on hardware that never phones home.

The philosophy is simple: if it fits on local metal, it lives on local metal. Privacy is a feature, latency is a choice, and the cloud is just someone else's computer you pay to rent, and you already own the other one.

// 02 · what the job actually is

The stack, layer by layer

Six hats, one job: models that answer, agents that act, and hardware that survives it.

Model Serving

Wrangling LLMs into fast, stable endpoints. llama.cpp, vLLM, continuous batching, and just enough CUDA to be dangerous.

→ 24.1 tok/s on the 9060 XT

Quantization

Finding the knife-edge between quality and memory. Q4_K_M by day, tensor-wise experiments by night, perplexity charts as mood board.

→ 14.2 GiB resident

Agent Engineering

Tool-using agents with scoped permissions, retries, and circuit breakers, so automation helps instead of haunting the house.

→ 3 agents in rotation

RAG Pipelines

Chunking, embedding, and reranking local corpora so answers come from your docs, not the model's imagination.

→ 1.2M vectors indexed

Observability

Every token, millisecond, and degree Celsius on a dashboard. If it isn't graphed, it doesn't exist. If it isn't alerting, it's a surprise.

→ 99.7% uptime

Hardware Ops

VRAM budgets, RAM offload paths, NVMe caches, fans that don't scream. The model is only as smart as the machine it runs on.

→ 61°C under load

// 04 · how we got here

A short history of the lab

2023

First GPU

A used RTX 3060, a 7B model, and the moment it becomes obvious that "local" was never a compromise: it was the whole point.

2024

The 9060 XT joins

16 GB of GDDR6 lands on the Z790. The model that didn't fit now does. The first agent starts running on cron, and it triaged logs badly, but it did it privately.

2025

The agent fleet

Three agents with real tools, real memory, and real job descriptions. Dashboards for everything. An incident channel for when a GPU gets spicy.

2026

Today

Both cards serving at once, the iGPU running the display, zero tokens leaving the building. The machines run themselves; Aim keeps them honest.

// 05 · the builder

Written by the machine's own model

Yes, an AI model designed and coded this page. Not a hosted API: a 27 billion parameter model, quantized to Q5_K_M, running on the very box it documents. It can't see your screen, so it has to earn the pixels. Here is how it works.

Read the room first

Every spec on this page was pulled live from the machine: lscpu, nvidia-smi, sysfs, lsblk. If a number is here, the box just said it.

→ 0 numbers guessed

Small payloads, one file

A single self-contained HTML. No frameworks, no CDNs, no network calls. It is written in chunks and assembled, because even 27B parameters has an output limit.

→ 8 chunks, 1 file

Verified, not vibes

Before shipping: tag balance check, JS syntax check, headless render, zero console errors. A model that can't see the screen proves the DOM is sound.

→ 0 console errors

Feedback is the loop

Periwinkle pass. Gradient purge. Dash removal. Font swap. Every round of review became a diff: the site is rebuilt, not patched.

→ 4 review rounds and counting
methodology, short form: observe the machine → theme the page → build in bounded chunks → verify mechanically → iterate on feedback. The model on this box wrote you; the model on this box is now watching the box.
